# Картка класової моделі: ShopOrders 

## 1. Таблиця сутностей предметної області

| Сутність | Роль у системі | Незмінний?  | Головний інваріант | Обґрунтування інженерного рішення |
| :--- | :--- | :--- | :--- | :--- |
| **OrderLine** | Позиція документа (рядок у замовленні) | **Так (`record`)** | `Quantity > 0` AND `UnitPrice >= 0` AND `ProductId > 0` | Рядок замовлення фіксує факт наміру купівлі конкретного товару за фіксованою ціною. Якщо клієнт змінює кількість, позиція замінюється новою, а не мутує. Має рівність за значенням. |
| **Customer** | Довідник учасників (покупець / замовник) | **Так (`record`)** | `Id > 0` AND `!string.IsNullOrWhiteSpace(FullName)` AND `Email.Contains('@')` | Профіль замовника для конкретного чека є фіксованим знімком даних. Значення валідуються одноразово в момент створення. |
| **Product** | Довідник об’єктів обліку (товар на складі) | **Ні (звичайний клас)** | `Id > 0` AND `Stock >= 0` AND `Price > 0` AND `!string.IsNullOrWhiteSpace(Name)` | Складський товар має змінюваний стан: залишок (`Stock`) зменшується при бронюванні/відвантаженні та збільшується при поверненні. |
| **Order** | Документ зі станом (кореневий агрегат) | **Ні (агрегат із контрольованими переходами)** | `Id > 0` AND `Lines.Count >= 0`; зміна `Lines` дозволена **виключно** у стані `New`; `TotalAmount >= 0` | Замовлення проходить життєвий цикл від створення до видачі чи скасування. Стан інкапсульовано: заборонено відкриті сетери, переходи здійснюються лише через методи предметної області. |

## 2. Життєвий цикл та таблиця переходів станів

### Перелік допустимих станів:
1. **New** — замовлення створено, наповнюється товарами, очікує підтвердження або розрахунку.
2. **Paid** — замовлення успішно оплачене клієнтом, кошти заблоковано/списано.
3. **Shipped** — замовлення укомплектовано та передано поштовій службі.
4. **Cancelled** — замовлення скасовано користувачем або системою.
5. **Returned** — товар повернуто покупцем на склад після отримання.

### Таблиця переходів між станами:

| Початковий стан | Кінцевий стан | Метод-перехід | Умова переходу (бізнес-правило / перевірка) |
| :--- | :--- | :--- | :--- |
| **New** | **Paid** | `Pay()` | `Lines.Count > 0` (замовлення містить щонайменше одну позицію) AND `Status == OrderStatus.New` |
| **New** | **Cancelled** | `Cancel(string reason)` | `Status == OrderStatus.New` AND `!string.IsNullOrWhiteSpace(reason)` |
| **Paid** | **Shipped** | `Ship(string trackingNumber)` | `Status == OrderStatus.Paid` AND `!string.IsNullOrWhiteSpace(trackingNumber)` (товар списано зі складу) |
| **Paid** | **Cancelled** | `Cancel(string reason)` | `Status == OrderStatus.Paid` (ініціюється процедура повернення коштів — refund) |
| **Shipped** | **Returned** | `Return(DateTime returnDate)` | `Status == OrderStatus.Shipped` AND `(returnDate - ShippedAt).TotalDays <= 14` (не минуло 14 днів з моменту відправлення) |

## 3. Інкапсуляція Order

1. **Колекція позицій:** Внутрішнє поле `_lines` реалізовано як `List<OrderLine>`, проте назовні віддається лише через інтерфейс `IReadOnlyList<OrderLine> Lines => _lines.AsReadOnly();`. Клієнтський код не може викликати методи `.Add()` чи `.Clear()` безпосередньо.
2. **Модифікація складу:** Додавання та видалення рядків здійснюється методами `AddLine(OrderLine line)` та `RemoveLine(int productId)`, які гарантують перевірку правила: `Status == OrderStatus.New`.
3. **Захист від невалідних станів:** Пряме присвоєння `order.Status = ...` заборонено (сетер є приватним: `public OrderStatus Status { get; private set; }`). Будь-яка спроба виконати неприпустимий перехід (наприклад, викликати `Ship()` для стану `New`) викидає виняток `InvalidOperationException`.
