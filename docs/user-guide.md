# Посібник користувача ShopOrders

## Запуск і перший екран

З кореня репозиторію виконайте `dotnet run --project src/ShopOrders.App`.
Одразу після запуску видно назву застосунку й головне меню:

```
ShopOrders — облік замовлень інтернет-магазину

1. Оформити замовлення (UC-01)
2. Оплатити замовлення (UC-02)
3. Скасувати замовлення (UC-03)
4. Відвантажити замовлення (UC-04)
5. Знайти замовлення (UC-05)
6. Звіт «Продажі за період» (UC-06)
7. Переглянути замовлення
0. Вихід
>
```

Введіть номер пункту й натисніть Enter. Після кожного сценарію меню показується знову.
Суми вводяться з комою або крапкою (`249,50` чи `249.50`), дати — у форматі `дд.мм.рррр`.
На екрані суми показуються з крапкою.

## Прохідні сценарії

### Оформити замовлення (UC-01)

Покупець № 4 — постійний, тому на суму 1797.00 грн діє знижка 5 %.
Неіснуючий артикул і нульова кількість не зупиняють сценарій: застосунок пояснює помилку
й питає знову.

```
> 1
Номер покупця: 4
Покупець: Ірина Л. (тест), статус: постійний
Вводьте позиції; порожній артикул завершує ввід.
Артикул: sku-108
Кількість: 1
Додано: Кавомолка ручна, 1 шт. × 1299.00 грн
Артикул: SKU-999
Товару SKU-999 немає в каталозі.
Артикул: SKU-101
Кількість: 0
Очікується ціле число, більше за нуль.
Кількість: 2
Додано: Кава мелена, 2 шт. × 249.00 грн
Артикул:
Замовлення оформлено.
Замовлення №81 від 10.11.2026, Ірина Л. (тест), стан: новий
  SKU-108 Кавомолка ручна: 1 шт. × 1299.00 = 1299.00 грн
  SKU-101 Кава мелена: 2 шт. × 249.00 = 498.00 грн
Сума: 1797.00 грн; знижка: 89.85 грн; до сплати: 1707.15 грн
```

### Оплатити замовлення (UC-02)

Недостатня сума відхиляється без зміни стану; повторна спроба з достатньою сумою проходить.

```
> 2
Номер замовлення: 81
Замовлення №81 від 10.11.2026, Ірина Л. (тест), стан: новий
  SKU-108 Кавомолка ручна: 1 шт. × 1299.00 = 1299.00 грн
  SKU-101 Кава мелена: 2 шт. × 249.00 = 498.00 грн
Сума: 1797.00 грн; знижка: 89.85 грн; до сплати: 1707.15 грн
Внесена сума, грн: 1700
Операцію відхилено: Внесено 1700.00, потрібно 1707.15, бракує 7.15 грн.

> 2
Номер замовлення: 81
...
Внесена сума, грн: 1710,00
Замовлення №81 оплачено. Решта: 2.85 грн.
```

### Скасувати відвантажене замовлення (UC-03, альтернатива 2а)

```
> 3
Номер замовлення: 5
Операцію відхилено: Замовлення №5 у стані Shipped: скасування заборонено.
```

### Знайти замовлення покупця (UC-05)

```
> 5
Порожній ввід означає «будь-яке значення».
Номер покупця: 1
Стан (New, Paid, Shipped, Cancelled):
Створено з (дд.мм.рррр):
Створено по (дд.мм.рррр):
   №  | Створено   | Покупець | Стан          | До сплати
   50 | 11.10.2026 |        1 | новий         |    1144.27
Знайдено замовлень: 1
```

### Звіт «Продажі за період» (UC-06)

Продажем вважається замовлення в стані Paid або Shipped; рядки групуються за днем оплати.

```
> 6
Початок періоду (дд.мм.рррр): 01.10.2026
Кінець періоду (дд.мм.рррр): 31.10.2026
Продажі за період 01.10.2026 – 31.10.2026
Дата       | Замовлень |      Сума |   Знижка |   Виручка
01.10.2026 |         1 |   3542.50 |    70.85 |   3471.65
02.10.2026 |         2 |   5181.00 |    94.06 |   5086.94
...
31.10.2026 |         2 |   4889.50 |   123.80 |   4765.70
Разом      |        26 |  82646.50 |  3350.59 |  79295.91
```

## Повідомлення про помилки

| Повідомлення | Що означає | Що робити |
|---|---|---|
| Очікується ціле число, більше за нуль. | номер чи кількість містить літери, дріб, нуль або від'ємне число | введіть ціле додатне число |
| Артикул має бути від 1 до 20 символів без пробілів. | артикул порожній, задовгий або з пробілом | введіть артикул як у каталозі, наприклад `SKU-104` |
| Товару … немає в каталозі. | артикул не знайдено | перевірте артикул у `data/products.json` |
| Очікується невід'ємна сума з не більше ніж двома знаками після коми. | сума від'ємна, має понад 2 знаки після коми чи пробіли | введіть суму у форматі `1234,50` |
| Очікується наявна дата у форматі дд.мм.рррр. | інший формат дати або неіснуючий день | введіть, наприклад, `01.10.2026` |
| Очікується один зі станів: New, Paid, Shipped, Cancelled. | невідома назва стану | введіть назву стану або залиште порожнім |
| Кінець періоду не може бути раніше за початок. | дати періоду переплутано | повторіть звіт із правильним порядком дат |
| Покупця №… не знайдено. / Замовлення №… не знайдено. | такого номера немає | перевірте номер через пошук (пункт 5) |
| Операцію відхилено: … заборонено. | дію не дозволяє поточний стан замовлення (таблиця 1.5 у docs/spec.md) | перевірте стан замовлення пунктом 7 |
| Операцію відхилено: Внесено …, бракує … грн. | внесено менше, ніж до сплати | повторіть оплату з повною сумою |
| Помилка файлу даних: … | файл даних зайнятий іншою програмою або немає прав на запис | закрийте файл в інших програмах і повторіть дію |
| Не вдалося завантажити дані: … | під час запуску немає файлу довідника або файл пошкоджено | перевірте теку `data`, відновіть файл з резервної копії |

## Де лежать дані й як зробити резервну копію

| Файл | Вміст |
|---|---|
| `data/products.json` | каталог товарів (60 умовних позицій) |
| `data/customers.json` | довідник покупців (50 умовних записів, не реальні особи) |
| `data/orders.seed.json` | початкові 80 замовлень; не змінюється застосунком |
| `data/orders.json` | робочий файл замовлень; створюється з `orders.seed.json` під час першого запуску |
| `logs/shoporders.log` | журнал роботи: час, рівень, сценарій, повідомлення |

Резервна копія: закрийте застосунок і скопіюйте `data/orders.json` в інше місце, наприклад
`copy data\orders.json backup\orders-2026-11-10.json`. Відновлення — скопіювати файл назад.
Щоб повернутися до початкових умовних даних, видаліть `data/orders.json`: під час наступного
запуску його буде створено заново з `orders.seed.json`.
