# Стандарт кодування проєкту ShopOrders

## 1. Загальні положення
Цей стандарт визначає обов'язкові правила іменування, форматування, структурування коду та оформлення комітів для навчального проєкту «Облік замовлень інтернет-магазину». Дотримання стандарту контролюється автоматично за допомогою середовища розробки, файлу `.editorconfig` та статичних аналізаторів коду (Roslyn / StyleCop).

## 2. Іменування
| Сутність | Конвенція | Приклад | Антиприклад |
| :--- | :--- | :--- | :--- |
| Клас, запис | PascalCase, іменник | `OrderLine` | `orderline` |
| Інтерфейс | I + PascalCase | `IOrderRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |
| Властивість | PascalCase, іменник | `UnitPrice` | `GetUnitPrice` |
| Приватне поле | _ + camelCase | `_lines` | `m_Lines` |
| Локальна змінна | camelCase | `totalAmount` | `ta` |
| Константа | PascalCase | `MaxLineCount` | `MAX_LINES` |
| Перелічення | PascalCase однина | `OrderStatus` | `OrderStatuses` |

## 3. Форматування
1. Відступ — рівно 4 пробіли; використання табуляції заборонено.
2. Довжина рядка — не більше ніж 100 символів.
3. Фігурні дужки — стиль Allman (відкриваюча дужка переноситься на новий рядок), обов'язкові навіть для однієї інструкції в тілі `if`.
4. Між членами класу — рівно один порожній рядок.
5. Директиви `using` — розміщуються на початку файлу, системні простори імен першими, невикористовувані директиви видаляються.
6. Простір імен — файлового рівня (наприклад, `namespace ShopOrders.Core.Domain;`).

## 4. Коментарі та документація
Коментарі повинні пояснювати причину та бізнес-логіку ухваленого технічного рішення, а не переказувати код словами.
// погано: коментар переказує код
// збільшуємо лічильник на одиницю
count = count + 1;
// добре: коментар пояснює причину рішення
// склад округлює вагу вгору, тому й тут Ceiling
weight = Math.Ceiling(rawWeight);

## 5.Структура проєкту
Рішення розділене на два незалежні рівні:

ShopOrders.Core — бібліотека класів, що містить бізнес-логіку, доменні моделі та правила предметної області.

ShopOrders.App — консольний застосунок, який відповідає за взаємодію з користувачем, введення/виведення даних та демонстрацію роботи програми.


## 6. Правила комітів
Коміти оформлюються за стандартом Conventional Commits:

//chore: — технічні завдання, налаштування інструментів, створення каркаса.
//feat: — додавання нової функціональності чи доменного скелета.
//docs: — додавання або зміна документації.
