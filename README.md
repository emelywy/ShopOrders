# ShopOrders

Консольний застосунок для обліку замовлень інтернет-магазину: оформлення, оплата,
скасування й відвантаження замовлень, знижка за сумою й статусом покупця,
пошук і звіт «Продажі за період».

## Автор і дисципліна

Варіант 1 «ShopOrders». Андрощук Діана, група 471.
Навчальна дисципліна «Конструювання програмного забезпечення», самостійна робота № 3.

## Швидкий старт

Потрібні .NET SDK 8.0 і Git. Три команди:

```bash
git clone https://github.com/emelywy/ShopOrders.git && cd ShopOrders
dotnet build
dotnet run --project src/ShopOrders.App
```

Застосунок читає дані з теки `data` поточного каталогу, тож запускайте його з кореня
репозиторію. Іншу теку даних можна передати аргументом:
`dotnet run --project src/ShopOrders.App -- D:\shop-data`.

## Структура рішення

| Проєкт | Призначення |
|---|---|
| `src/ShopOrders.Domain` | сутності, стани замовлення, таблиця переходів, власний виняток домену |
| `src/ShopOrders.Application` | сервіси сценаріїв, інтерфейси сховищ, політика знижки, барикада валідації |
| `src/ShopOrders.Infrastructure` | сховище JSON, довідники, журнал у файл, системний годинник |
| `src/ShopOrders.App` | консольне меню, ввід і вивід, композиційний корінь `Program.cs` |
| `tests/ShopOrders.Tests` | модульні тести xUnit із ручними тестовими дублерами |

Схема залежностей і пояснення — у [docs/architecture.md](docs/architecture.md).

## Тести й покриття

```bash
dotnet test /p:CollectCoverage=true /p:CoverletOutputFormat=cobertura
```

Межа вимірювання — бібліотеки `ShopOrders.Domain` і `ShopOrders.Application`
(інфраструктуру й консоль виключено у `tests/ShopOrders.Tests/ShopOrders.Tests.csproj`).
Поточне рядкове покриття: **__ %**, покриття гілок: **__ %** (останній прогін CI).

Локальний еквівалент усього конвеєра CI однією командою:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/check.ps1   # Windows
./scripts/check.sh                                             # Linux, macOS
```

Скрипт перевіряє формат, складає Release з `-warnaserror` і запускає тести з порогом
рядкового покриття 70 %.

## Обмеження й відомий борг

- Немає повернення товару після відвантаження й повернення коштів за скасоване оплачене замовлення.
- Залишки на складі не контролюються: замовити можна будь-яку кількість товару.
- Файл замовлень читається й записується цілком; на десятках тисяч записів це стане повільним.
- Одночасна робота кількох операторів з однією текою даних не підтримується.
- Реєстр залишкового боргу — [docs/tech-debt.md](docs/tech-debt.md).
